# Phase 9: レビュー・監査結果（運用フィードバック対応）

> SP-8（インクリメンタルレビューパイプライン）に基づき、コードレビュアー・システム監査官の
> 独立レビューを指摘ゼロまで反復する。本書はその経過と最終結果の記録。

## イテレーション 1

### システム監査官（対象: プロキシ新設・スナイプ・画面別戦略・履歴保存・リアルタイム損益）

Critical/High なし・Medium 3 件・Low 2 件 → **全件修正済み**

| # | Severity | 指摘 | 対応 |
|---|----------|------|------|
| AUDIT-P9-1 | Medium | アーカイブ約定履歴の件数上限（10×100件）では Firestore の 262144 バイト制限を保証できず、超過時は全 persist の同期がサイレントに恒久失敗する。別端末の古い状態による巻き戻り経路にもなる。data-design.md の「容量保護」記述とコードの保証内容が不一致 | `shared/persistBudget.ts` を新設し、保存前に**シリアライズ後の実測バイト数**（UTF-8・予算 200KB）で保証。超過時は古いアーカイブの明細 → 本体の順で切り詰め（実行中ポートフォリオは不変）。同期失敗はセッション初回のみ CRYPTIA-E601 でユーザー通知。data-design.md を実際の保証内容に更新。単体テスト 5 件追加 |
| AUDIT-P9-2 | Medium | プロキシの IP 30/分がキャッシュヒットでも消費されるため、本機能のターゲット環境（企業 NAT）で正規ユーザー 2〜3 人が枯渇させる | `cachedProxyJson` に集約し、**キャッシュヒット・inflight 合流はクォータ無消費**（ミス時のみ消費）へ変更。上限も 60/分へ調整 |
| AUDIT-P9-3 | Medium | 上流ホスト単位の総量防御がなく、分散 IP + キャッシュミス誘発（pairs の任意 addrs 組合せ）で上流規約（DexScreener 約300/分・CoinGecko 無料枠）を超過し、egress IP の throttle で全プロキシ利用者が停止し得る | 上流ホスト単位のバジェット（dexscreener 60/分・coingecko 4/分・rpc 30/分、fresh はコスト 11 で計上）を追加。超過・ビルド失敗時は**期限切れキャッシュを stale で返す**（stale-while-error）。tickers TTL を 30s へ延長 |
| AUDIT-P9-4 | Low | 信頼 IP 抽出（XFF 右端 + NUXT_TRUSTED_PROXY_HOPS）が ai-rate-limit と dexProxy に重複し、片側修正でドリフトするリスク | `rateLimit.ts` の `clientIpFromForwarded()` に一本化し両者から参照 |
| AUDIT-P9-5 | Low | `/api/solana/fresh` の最悪応答（約44s）がクライアントタイムアウト（25s）を超過 | サーバー側に全体デッドライン 20s を設け、超過時は RPC・再発行照合をスキップしシグナル null の部分結果で返す |

監査で確認された安全事項（指摘なし）: オープンプロキシ/SSRF 不可（宛先固定・入力検証）、
キャッシュ/リミッタのメモリ上限、スナイプはデモ資金のみ（署名フロー不変）、
投資助言に該当しない旨の明示、シークレットのハードコードなし、下位互換パース、
テストゲート・既存レートリミットの緩和なし。

### コードレビュアー（対象: 同上 + ウォレット修正・監査修正後の最終スナップショット）

High 1 件・Medium 3 件・Low 8 件 → **全件修正済み**

| # | Severity | 指摘 | 対応 |
|---|----------|------|------|
| ISSUE-P9-H1 | High | 検索リスト外の保有ペア（スナイプ対象等）は fetchTokens の held 引き継ぎで価格が凍結し、`refreshHeldPairs` は「リストに存在しないペアのみ」対象のため 2 ティック目以降更新されない。表示タイマーはページ滞在中のみで、**バックグラウンドではラダー/AI が凍結価格で執行される**（損切り不発火） | `refreshHeldPairs` を廃止し、`fetchTokens()` 成功後（= 毎ティック）に `refreshDisplayPrices()`（watchedPairs∪positions を replace-or-push で個別取得）を必ず await。バックグラウンドでも 30s ごとに実勢価格で執行される |
| ISSUE-P9-M1 | Medium | スナイプラダー [0.3,0.3,0.2] は残数量比のため実際の配分が元本比 30%→21%→9.8%（ムーンバッグ 39.2%）となり、UI・ガイドの「30/30/20・残り20%」と定量的に不一致 | sellRatio を [0.3, 3/7, 0.5] に修正（検算: 残 0.7→0.4→0.2 = 元本比 30/30/20 + ムーンバッグ 20%）。注釈に残数量比の意味論と検算を明記。累積配分テストを追加 |
| ISSUE-P9-M2 | Medium | market ストアのプロキシフォールバックが毎回直接→失敗→プロキシ（sticky でなく api-design.md と矛盾）。遮断環境で毎 15s に最大 8s の無駄待ち + 応答遅延時の多重フェッチで古い応答が新しい tickers を上書きし得る | solana/wallet と同じ sticky 切替（`_via`・自己回復つき）を `_fetchMarkets()` に実装し、`fetchTickers` に in-flight ガード（`_fetching`）を追加 |
| ISSUE-P9-M3 | Medium | insights のキャッシュキーに戦略が含まれず、画面別ピッカーで切り替えても表示中インサイトが最大 5 分間サイレントに不一致 | キャッシュキーに `docFor('insights').id` を含め（`insightKey`）、ページ側で `activeByContext.insights` を watch して切替時に再生成 |
| ISSUE-P9-L1 | Low | セッション終了後も watchedPairs が残り 10s ごとに不要なペア取得が継続（クォータ浪費） | `refreshDisplayPrices` を「portfolio があるときのみ」実行に変更 |

| ISSUE-P9-L3 | Low | Twitter/Telegram の URL 判定が部分一致（"dropbox.com/x.com/…" 等を誤検出） | `new URL().hostname` の厳密比較（サブドメイン許容）へ変更。誤検出防止テストを追加 |
| ISSUE-P9-L4 | Low | 売りゼロ・買い多数（最良の買い優勢）で需給ボーナスが付かない単調性の破れ | `sells24h === 0` を買い優勢として扱う分岐を追加。テスト追加 |

## イテレーション 2（検証レビュー）

独立レビュアーによる修正の検証。**12 件すべて「解消」判定・新規指摘ゼロ**。

- H-1: `refreshHeldPairs` 廃止 + 毎ティックの `refreshDisplayPrices()` で解消を確認。
  `_pricesBusy` 競合時も価格鮮度は最大 ~10s に有界（無期限凍結は構造的に不可能）、
  モック時の早期 return・無限ループなし・クォータ内（screen 2/分 + pairs ≤8/分 < 60/分）を精査済み
- M-1: `checkLadder` の発火順（|trigger| 昇順）と残数量への順次適用の意味論一致、
  累積配分テスト・ユーザーガイド・画面文言の定量一致を確認
- M-2/M-3/L-1〜L-8: 実装・テスト・ドキュメントの全てで解消を確認
- 新規問題の探索: onMounted の明示的更新はフォールバックとして妥当（プロキシ 8s キャッシュで重複吸収）、
  復元時の並行 fetchTokens も原子的置換のため安全 — 成立する新規問題なし
- テスト 127/127 パスを検証側でも再実行して確認

### オペレーターへの引き継ぎ事項

1. **追加の repository secrets / variables は不要**（新設 API ルートは既存の Functions デプロイに含まれる）
2. 本番で「DexScreener に接続できない」が再発した場合はバナーの「再試行」を案内。
   それでも失敗する場合は Cloud Logging で `CRYPTIA-E102` を検索（プロキシ側の上流障害）
3. ウォレット残高が取得できない場合（CRYPTIA-E505）は公開 RPC の混雑が原因。
   恒久対策として有料 RPC（Helius / QuickNode 等）の URL 差し替えを将来検討（現在は公開 RPC + プロキシ）

## 追加対応（同スプリント内のオペレーター報告）

- **残高取得スタック（スクリーンショット報告）:** 公開 Solana RPC のブラウザ遮断が原因。
  読み取り専用 RPC プロキシ（許可メソッド 2 種のみ・BR-1 維持）+ 明示的エラー表示（CRYPTIA-E505）で解消
- **マルチウォレット対応:** Phantom / Bitget Wallet / Solflare / 汎用 Phantom 互換の検出・選択接続
