# Phase 3: 非機能要件

## パフォーマンス

| 項目 | 基準 |
|------|------|
| 初期表示（キャッシュ済みPWA） | 200ms 以下でシェル表示、2s 以内に初期データ描画 |
| 価格更新間隔 | 15 秒（API レートリミット内。UI 上は更新時刻を明示） |
| バブルマップ描画 | 60fps 目標・30fps 下限（モバイル）。銘柄数上限 30 で制御 |
| AI インサイト応答 | 10s 以内（超過時はローディング表示と再試行導線） |
| 検索/フィルタ操作 | 100ms 以下（クライアント内処理） |

## セキュリティ

| 項目 | 基準 |
|------|------|
| データ機密度 | 個人資産情報（デモ履歴・戦略・実トレードログ）= 中機密。秘密鍵 = 取り扱わない（最重要） |
| 認証 | Firebase 匿名認証（MVP）。Firestore Security Rules で uid 単位のアクセス制御 |
| API キー | サーバー側（Cloud Functions / Nitro server）でのみ保持。クライアントへ露出しない |
| シークレット管理 | repository secrets（GitHub Actions）+ GCP Secret Manager / 環境変数 |
| ウォレット | 署名はウォレット拡張内で完結。トランザクション内容を署名前に画面で明示 |
| 入力検証 | サーバー API は全入力を検証（銘柄ID・数値範囲・文字列長） |

## 可用性・運用

| 項目 | 基準 |
|------|------|
| 稼働率 | Firebase Hosting / Cloud Functions の SLA に準拠（MVP は単一リージョン asia-northeast1） |
| 外部API障害時 | 価格: 最終キャッシュ表示＋警告 / AI: テクニカル指標フォールバック / DEX: リスト非表示＋案内 |
| 監視 | Cloud Logging + Firebase コンソール。サーバー API はエラーコード付き構造化ログ |
| エラーコード | `CRYPTIA-Exxx` 形式で一元管理（コードベース `shared/errors.ts`） |

## 同時接続・環境

- 想定同時接続: 〜1,000（MVP）。ステートレスなサーバー API + CDN 配信でスケール
- 対応環境: 最新 Chrome / Safari / Edge（PC・iOS・Android）。PWA インストール対応
- レスポンシブ: 320px〜。モバイルは下部タブナビゲーション、PC はサイドナビゲーション
